# 印刷件黄色水印检测方案说明书

| 项目 | 内容 |
|---|---|
| 文档状态 | 草稿 v0.1 |
| 适用工程 | `WatermarkDemo`（Android / Kotlin / CameraX / OpenCV） |
| 配套脚本 | `水印/yellow_enhance.py`（Python / OpenCV，离线复现同一管线） |
| 范围 | 相机拍摄印刷件，**增强出水印图案供人眼或后续算法判读**。不含二维码识别，不含图片文件内嵌水印 |

---

## 1. 背景与目标

### 1.1 背景

某款现有“数字水印”App 能在手机相机预览中实时、稳定地显示印刷件上的隐形水印；自研原型只能在很浅的程度、或特定角度下看到。需要弄清现有 App 的做法，找出差距，形成可落地的方案。

### 1.2 目标

1. 相机对准印刷件后，**实时**（目标 ≥ 15 fps，1080p）输出水印被增强后的画面。
2. 对拍摄角度、局部阴影和反光不敏感。
3. 参数可调、阶段可视，便于现场对比和调参。

### 1.3 非目标

- 不做二维码或印章 ID 的自动解码。
- 不处理 JPG/PNG 文件内部嵌入的数字水印。
- 不做防伪结论判定（真/假），只输出增强图。

---

## 2. 依据：对现有 App 的分析结论

分析对象是手机上已安装 App 的原生库 `libYellowWatermark.so` 与 `libGABStamp.so`（arm64）。方法是读取导出符号，并对关键函数做静态反编译，**没有动态调试，也没有在设备上验证**。

### 2.1 现有 App 的实时流程

```
相机帧(YUV NV21)
  └─ 转 BGR
      └─ 取 B 通道            ← 黄色油墨吸收蓝光，B 通道对比最大
          └─ 3×3 锐化滤波
              └─ 腐蚀/膨胀（核 1×1，实际是空操作）
                  └─ 逐像素曲线（两种，见 4.4）
                      └─ 直方图均衡
                          └─ 对比度拉伸
                              └─ 显示（回传 Java 层）
```

另有一条“找纸面”的前置流程，用于黄色矩形水印：

```
灰度图 → 开运算 → 闭运算 → 自适应阈值 → 外轮廓 → 多边形近似
  → 保留凸四边形且面积占画面 10%~90% → 取最大 → 透视矫正 → 增强
```

### 2.2 关键发现

| 编号 | 发现 | 置信度 |
|---|---|---|
| F1 | 增强只作用在 **B 通道**，不是亮度或灰度 | 高（`split` 后取第 0 个元素，输入为 BGR） |
| F2 | 3×3 核为 `[0,-1,0; -1,5,-1; 0,-1,0]` | 高（从全局构造函数读出） |
| F3 | 全库所有腐蚀/膨胀的结构元素都是 **1×1**，等于空操作 | 高（同上） |
| F4 | 增强是**给人看的**，原库的矩形水印路径没有位解码，增强图直接回传 Java 层显示 | 中（调用链推断，未见解码函数） |
| F5 | 定位用“自适应阈值 + 轮廓 + 凸四边形 + 面积 10%~90%”，随后**透视矫正**再增强 | 高（参数已读出） |
| F6 | 光照不均靠曲线和均衡化硬扛，没有显式的光照归一化 | 中 |

### 2.3 自研原型的差距（对照）

| 现象 | 推测原因 |
|---|---|
| 只在特定角度能看到 | 没做透视矫正；反光与阴影随角度变化 |
| 水印很浅 | 没取 B 通道，或曲线没把 150~170 附近的灰度段拉开 |
| 二值化后大片全黑 | 全局阈值被光照梯度击穿 |

## 3. 方案总览

在原流程基础上做三处改动：**增加纸面检测兜底**、**增加光照归一化（可选）**、**阶段全部可视**。

```
RGBA 帧
  ├─ 取通道（默认 B）
  ├─ 纸面检测 ──┬─ 成功 → 透视矫正
  │            └─ 失败 → 使用整幅画面
  ├─ [可选] 光照归一化
  ├─ 3×3 锐化 + 形态学
  ├─ 逐像素曲线
  ├─ 直方图均衡
  └─ 1%~99% 分位拉伸 → 显示 / 保存
```

| 步骤 | 来源 | 是否可关 |
|---|---|---|
| 取通道 | 原库 | 可切换 B/G/R/亮度 |
| 纸面检测 + 矫正 | 原库参数 + **本项目兜底** | 可关 |
| 光照归一化 | **本项目新增** | 可关，默认关 |
| 锐化 + 形态学 | 原库 | 参数可调 |
| 曲线 | 原库 | 两种模式 |
| 均衡 + 拉伸 | 原库（拉伸为近似） | 固定 |

## 4. 详细设计

### 4.1 取通道

输入为 CameraX 的 `RGBA_8888` 帧，Mat 中通道顺序为 R、G、B、A，因此 **B 通道索引为 2**。亮度模式使用 `COLOR_RGBA2GRAY`，仅用于对比。

### 4.2 纸面检测与透视矫正

处理对象是缩小到长边 640 的灰度图（检测不需要高分辨率）。

**方法一：沿用原库**

1. 开运算：腐蚀、膨胀，矩形核 5（原库 7，按缩小比例换算）。
2. 闭运算：膨胀、腐蚀，矩形核 31（原库 53，同上换算）。
3. `adaptiveThreshold`：均值法，二值化，块大小 27，C = 7。
4. 外轮廓，`approxPolyDP`（精度 = 周长 × 0.02）。
5. 筛选：恰好 4 个顶点、凸、面积在画面的 10%~90%，取面积最大者。

**方法二：本项目新增兜底**（方法一失败时触发）

实测发现方法一在“纸放在均匀桌面上”时失效：自适应阈值把纸面和桌面都判成白色（合成图上白色占 94%），外轮廓是整幅画面，被 90% 上限丢弃。推测原库的参数更适合框出**印在纸上的矩形标记框**。

兜底做法：

1. 对闭运算结果做 **Otsu** 二值化。
2. 取外轮廓的**凸包**。
3. 近似精度依次尝试 0.02、0.03、0.04、0.06，直到得到 4 个顶点的凸多边形，容忍纸边卷曲。
4. 面积筛选同方法一。

**排序与矫正**

- 角点按 `x+y` 最小为左上、最大为右下，`y−x` 最小为右上、最大为左下排序，并换算回原图坐标。
- 输出尺寸取上下两边较长者为宽、左右两边较长者为高，长边上限 1280。
- 使用 `getPerspectiveTransform` + `warpPerspective`（双线性）。

**失败处理**：两种方法都找不到时，**使用整幅画面**，不报错、不中断；UI 提示“未检测到纸面四边形”。

### 4.3 光照归一化（本项目新增，可选）

目的是去掉阴影和反光造成的低频亮度变化。

```
f   = 通道图(float) + 1
bg  = 高斯模糊(缩小 8 倍的 f, sigma/8) 再放大回原尺寸 + 1
out = f / bg × target      （饱和转 8 位）
```

- 在 1/8 尺寸上估计背景，避免对 1080p 做 180 像素宽的高斯核。
- `target` 是归一化后的纸面亮度，**必须大于 170**，否则 4.4 的曲线会把整幅图清零（实测 target=128 时全黑，190 时正常）。
- 默认关闭，以保持与原库一致；对比实验时打开。

### 4.4 逐像素曲线

两种，对应原库两条路径：

**extract 曲线**（来自 `extractYellowWatermarkOneChannelOnly`）

| 输入 v | 输出 |
|---|---|
| ≤ 150 | 0 |
| 151 ~ 170 | v − 150（即 1 ~ 20） |
| ≥ 171 | min(v, 235) + 20（即 191 ~ 255） |

它把 150~170 这段狭窄灰度拉成接近黑白，前提是纸面亮度已在 170 以上。

**useNew 曲线**（来自 `FirstExtractQrFinal`）

```
v > dv ? min(255, v + at255) : max(0, v − rt0)
```

`dv` 默认 3；`at255`、`rt0` 由 Java 层运行时设置，**默认值未找到**，工程里默认 0，需现场调。

### 4.5 均衡与拉伸

- `equalizeHist`。
- 拉伸：原库 `contrastStretchNew` 的细节未还原，这里用 1%~99% 分位线性拉伸近似。
- 注意：整幅图上做 `equalizeHist` 会把纸面细微亮度起伏放大成花斑（实测），后续建议改为只在矫正后的纸面区域内做，或使用 CLAHE。

## 5. 工程设计（WatermarkDemo）

### 5.1 分层

```
MainActivity ─ MainScreen(Compose) ─ MainViewModel ─ WatermarkEnhancer ─┬─ PaperDetector
                                                                         ├─ FrameConverter
                                                                         └─ FrameSaver
```

| 类 | 职责 |
|---|---|
| `FrameConverter` | `ImageProxy`（RGBA）→ 直立的 OpenCV Mat，处理 rowStride 与旋转 |
| `PaperDetector` | 纸面检测、透视矫正、检测结果叠加图 |
| `WatermarkEnhancer` | 按阶段执行管线，返回 `EnhanceResult(bitmap, paperFound)` |
| `EnhanceParams` | 全部参数与固定常量 |
| `MainViewModel` | 持有参数与 UI 状态；在分析线程处理帧；保存请求在下一帧执行 |
| `FrameSaver` | 通过 MediaStore 存 PNG 到 `Pictures/WatermarkDemo` |

### 5.2 阶段

`SOURCE → DETECT → RECTIFY → FLAT_FIELD → HIGH_PASS → CURVE → EQUALIZE → STRETCH`。UI 可选择只显示某一阶段，后续阶段不会执行，省时间。

### 5.3 性能与资源

- 分析线程单线程，`STRATEGY_KEEP_ONLY_LATEST`，慢帧自动丢弃，不堆积。
- 所有 `Mat` 在 `finally` 中释放；`WatermarkEnhancer` 内部用列表跟踪中间结果。
- 检测在 640 长边上做，开销远小于全分辨率。
- 帧率与单帧耗时显示在界面底部状态栏，**目前没有实测数据**。

### 5.4 保存

“保存”按钮在**下一帧**同时存**原始帧**和**当前阶段输出**，文件名带时间戳。原始帧用于回到桌面脚本里复现同一结果。

## 6. 验证方案

### 6.1 已完成

| 项目 | 方法 | 结果 |
|---|---|---|
| 管线各阶段正确性 | Python 脚本在屏幕截图上跑 | 红色印章、手写字被增强；阴影区被固定曲线打黑（复现了自研原型的症状） |
| 光照归一化 | 同上，target=190 | 阴影区黑噪点基本消除；均衡化仍放大纸面花斑 |
| 纸面检测（Python） | 合成图：纸面透视变形后贴到深色背景 | 方法一失败，方法二成功，矫正后印章恢复正圆 |
| 纸面检测（真实截图） | 两张样图 | 均未检测到，回退整幅画面（样图 1 纸张铺满画面；样图 2 纸面被物体切碎）。**不能证明检测在真实场景可用** |
| 编译 | Gradle | Debug APK 构建通过 |

### 6.2 未完成（必须做）

1. **用真实水印样张验证。** 目前所有图像都是屏幕截图，黄色点阵在截图里已丢失，没有任何一次实验真正看到了隐形水印。需要 PNG 原始帧。
2. 手机实机跑通 Kotlin demo，记录 fps、单帧耗时、发热。
3. 对比 B / G / R / 亮度四种通道下水印的可见度。
4. 对比有无纸面矫正、有无光照归一化，在 0°、30°、60° 拍摄角度下的效果。
5. 确定 `at255`、`rt0` 的合适取值。
6. 检测失败率统计：不同桌面颜色、纸张大小、遮挡。

### 6.3 建议的评价指标

- **人眼**：5 档可见度评分（1 看不到，5 清晰），多人盲评。
- **客观**：在矫正后的区域上，取水印图案与背景的局部对比度（水印区域均值与背景均值之差 / 背景标准差）。
- **稳定性**：连续 100 帧中“可见度 ≥ 3”的帧占比。

## 7. 风险与限制

| 风险 | 说明 | 缓解 |
|---|---|---|
| 样本缺失 | 没有真实原始帧，所有结论的置信度受限 | 优先补充样张 |
| 反编译推断 | F4、F6 为推断；曲线参数 `at255`、`rt0` 未知 | 现场调参；必要时动态调试确认 |
| 检测适用面 | 方法一偏向“印在纸上的框”，方法二偏向“整张纸”；两者都可能被其他物体干扰 | 失败回退整幅；UI 显示检测状态 |
| 手机差异 | 不同相机的白平衡、HDR 和降噪会影响黄色点阵可见度 | 固定曝光/白平衡的方案待评估（CameraX 的 Camera2 互操作） |
| 打印差异 | 油墨、纸张、点阵密度不同，曲线阈值（150/170/235）可能不通用 | 把阈值做成可调参数，或改为按直方图自适应 |
| 性能 | 1080p 下的 fps 未测 | 先测；必要时降分辨率或只处理矫正后的 ROI |

---

## 8. 合规与边界

- 本方案基于对已安装 App 的**静态分析**，只借鉴了处理思路与数值参数，工程代码为独立编写，**不包含原 App 的代码或二进制**。
- 反编译输出（含第三方库代码）保存在 `水印/analysis/`，不应随产品发布，也不建议入公共仓库。
- 分析中看到原库含授权与试用期逻辑，以及一个名为 `WEAKWATERMARK_PASSWORD` 的符号。**本项目没有读取或使用任何授权、密钥相关的内容**，也不应读取。
- 若方案将产品化，建议在发布前请法务评估逆向分析所得信息的使用边界。

## 附录 B：用 Python 脚本复现

```bash
python yellow_enhance.py frame.png -o out --mode extract --rectify --flatfield --autocrop
```

- `--rectify`：纸面检测 + 矫正。
- `--flatfield`：光照归一化（`--sigma`、`--target` 可调）。
- `--autocrop`：仅用于屏幕截图，裁掉黑边和状态栏；真实相机原始帧不要加。
- 输出 `*_stages.jpg`（各阶段拼图）和 `*_final.png`。
